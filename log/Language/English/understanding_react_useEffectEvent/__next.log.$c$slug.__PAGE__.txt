<h1 id="heading-02-00-00">Vocabulary</h1>
<h2 id="heading-02-01-00">stale / stale closure</h2>
<p><strong>Stale</strong> means no longer fresh, current, or up to date. In React, a <strong>stale closure</strong> appears when a callback still reads values from an older render. The function is still running correctly from JavaScript's point of view, but the data it sees is outdated, which creates subtle bugs.</p>
<ul>
<li><strong>Example</strong>
<blockquote>
<p>"The interval callback had a stale closure, so it kept logging the initial count."</p>
</blockquote>
</li>
<li><strong>Related expressions</strong>
<ul>
<li><strong>outdated</strong>: synonym — no longer fresh, current, or up to date</li>
<li><strong>obsolete</strong>: synonym — no longer used or produced</li>
<li><strong>old</strong>: synonym — from an earlier time; not new</li>
<li><strong>fresh</strong>: antonym — newly made or obtained; current</li>
<li><strong>up-to-date</strong>: antonym — including the latest information</li>
<li><strong>current</strong>: antonym — happening or existing now</li>
</ul>
</li>
<li><strong>Common collocations</strong>
<ul>
<li><strong>stale closure</strong>: callback still reads values from an older render</li>
<li><strong>stale state</strong>: component state that a handler no longer reflects</li>
<li><strong>stale data</strong>: cached or fetched data that is no longer current</li>
<li><strong>stale value</strong>: any value in scope that has since been updated</li>
</ul>
</li>
</ul>
<h2 id="heading-02-02-00">closure</h2>
<p>A <strong>closure</strong> is a function together with the variables it captured from its surrounding scope at creation time. This is a core JavaScript feature and very useful for encapsulation. In UI code, however, the same feature can become tricky when a long-lived callback keeps old state.</p>
<ul>
<li><strong>Example</strong>
<blockquote>
<p>"This handler is a closure over <code>roomId</code> and <code>isMuted</code>."</p>
</blockquote>
</li>
<li><strong>Related expressions</strong>
<ul>
<li><strong>lexical scope</strong>: related — the region of code where a name is visible</li>
<li><strong>captured variables</strong>: related — variables enclosed by a function closure</li>
<li><strong>global state</strong>: contrast — state shared across the entire application</li>
</ul>
</li>
<li><strong>Common collocations</strong>
<ul>
<li><strong>create a closure</strong>: form a function that captures surrounding variables</li>
<li><strong>closure over state</strong>: function that captures component state at creation time</li>
<li><strong>closure scope</strong>: the lexical scope a closure can still access</li>
</ul>
</li>
</ul>

<h2 id="heading-02-22-00">footguns</h2>

<h1 id="heading-03-00-00">Grammar</h1>
<h2 id="heading-03-01-00">Source sentence</h2>
<blockquote>
<p>So when a subscription calls the onMessage it captured on render 1, it still reads the current callback with current values.</p>
</blockquote>
<p><strong>Meaning:</strong> Even when a subscription calls the <code>onMessage</code> captured during render 1, <code>useEffectEvent</code> still reads the latest callback with the latest values.</p>
<h2 id="heading-03-02-00">Sentence structure</h2>
<pre><code>So [when-clause], [main clause]
</code></pre>





















<table><thead><tr><th>Part</th><th>Role</th></tr></thead><tbody><tr><td><strong>So</strong></td><td>discourse marker — connects this sentence to the previous explanation</td></tr><tr><td><strong>when a subscription calls ...</strong></td><td>adverbial clause of time — "when ~ happens"</td></tr><tr><td><strong>it still reads ...</strong></td><td>main clause — states what still happens</td></tr></tbody></table>
<h2 id="heading-03-03-00">When-clause breakdown</h2>
<p><strong>when a subscription calls the onMessage (that) it captured on render 1</strong></p>
<pre><code>when
  a subscription              ← subject
  calls                       ← verb
  the onMessage               ← object
    (that) it captured on render 1   ← relative clause modifying onMessage
</code></pre>
<h3 id="heading-03-03-01">the onMessage (that) it captured on render 1</h3>
<p>This is an <strong>object relative clause</strong> with <strong>that</strong> omitted.</p>
<p>Expanded form:</p>
<blockquote>
<p>the onMessage <strong>that</strong> it captured on render 1</p>
</blockquote>
<p>Underlying sentence:</p>
<blockquote>
<p>it captured <strong>the onMessage</strong> on render 1</p>
</blockquote>
<ul>
<li><strong>it</strong> = the subscription (or the effect closure)</li>
<li><strong>captured</strong> = verb</li>
<li><strong>the onMessage</strong> = object → relative pronoun position</li>
<li><strong>on render 1</strong> = at the time of the first render</li>
</ul>
<h2 id="heading-03-04-00">Main clause breakdown</h2>
<p><strong>it still reads the current callback with current values</strong></p>





























<table><thead><tr><th>Element</th><th>Meaning</th></tr></thead><tbody><tr><td><strong>it</strong></td><td><code>useEffectEvent</code> (or its stable reference mechanism)</td></tr><tr><td><strong>still</strong></td><td>even so; contrary to expectation</td></tr><tr><td><strong>reads</strong></td><td>accesses / refers to internally</td></tr><tr><td><strong>the current callback</strong></td><td>the latest version of the callback</td></tr><tr><td><strong>with current values</strong></td><td>carrying the latest values (prepositional phrase modifying callback)</td></tr></tbody></table>
<h2 id="heading-03-05-00">Key grammar points</h2>
<ol>
<li><strong>So</strong> — introduces a result or follow-up conclusion.</li>
<li><strong>when-clause</strong> — sets the timing or condition.</li>
<li><strong>Omitted that</strong> — common in object relative clauses.</li>
<li><strong>capture</strong> — in closure contexts, "to hold onto a value or function from a specific render."</li>
<li><strong>on render 1</strong> — "during / at the time of render 1."</li>
<li><strong>still</strong> — emphasizes that the outcome does not change even under the condition above.</li>
<li><strong>with current values</strong> — prepositional phrase describing the callback.</li>
</ol>
<h2 id="heading-03-06-00">Why this contrast matters (React context)</h2>
<p>A normal effect callback may read <strong>stale values</strong> from an older render. <code>useEffectEvent</code> keeps a <strong>stable reference</strong>, so even if the subscription still calls the <code>onMessage</code> captured on render 1, execution still sees the <strong>current callback with current values</strong>.</p>
<hr>
<h2 id="heading-03-07-00">Relative clauses</h2>
<p>A <strong>relative clause</strong> modifies a noun (the <strong>antecedent</strong>) and is introduced by a relative pronoun such as <strong>who</strong>, <strong>which</strong>, <strong>that</strong>, or <strong>whose</strong>.</p>
<p>Relative clauses are classified by the role the relative pronoun plays inside the clause.</p>
<h3 id="heading-03-07-01">Subject relative clause</h3>
<p>The relative pronoun is the <strong>subject</strong> of the clause.</p>
<blockquote>
<p>the developer <strong>who wrote this hook</strong></p>
</blockquote>
<p>Expanded:</p>
<blockquote>
<p>the developer = subject, who wrote this hook</p>
</blockquote>
<ul>
<li><strong>who / which / that</strong> is usually <strong>not omitted</strong></li>
<li>Example: The callback <strong>that runs on every message</strong> is stable.</li>
</ul>
<h3 id="heading-03-07-02">Object relative clause</h3>
<p>The relative pronoun is the <strong>object</strong> of the clause.</p>
<blockquote>
<p>the onMessage <strong>(that) it captured on render 1</strong></p>
</blockquote>
<p>Expanded:</p>
<blockquote>
<p>it captured <strong>the onMessage</strong> on render 1</p>
</blockquote>
<ul>
<li><strong>that / which / whom</strong> is often <strong>omitted</strong>, especially <strong>that</strong></li>
<li>If the clause already has a subject (<code>it</code>), the relative pronoun is likely an object</li>
</ul>
<h3 id="heading-03-07-03">Possessive relative clause</h3>
<p>The relative pronoun shows <strong>possession</strong>.</p>
<blockquote>
<p>the component <strong>whose state is stale</strong></p>
</blockquote>
<p>Expanded:</p>
<blockquote>
<p>the component's state is stale</p>
</blockquote>
<ul>
<li><strong>whose</strong> is followed by a noun: <strong>whose state</strong>, <strong>whose values</strong></li>
<li>For things, formal style may use <strong>of which</strong>: the API, <strong>the behavior of which</strong> is tricky</li>
</ul>
<h2 id="heading-03-08-00">Relative clause comparison</h2>





























<table><thead><tr><th>Type</th><th>Pronoun role</th><th>Omission</th><th>Example</th></tr></thead><tbody><tr><td><strong>Subject</strong></td><td>subject</td><td>rarely omitted</td><td>the dev <strong>who built it</strong></td></tr><tr><td><strong>Object</strong></td><td>object</td><td>often omitted</td><td>the hook <strong>(that) I use</strong></td></tr><tr><td><strong>Possessive</strong></td><td>possession</td><td>not omitted</td><td>the file <strong>whose name is long</strong></td></tr></tbody></table>
<h2 id="heading-03-09-00">How to identify the type</h2>
<p>Turn the relative clause into a standalone sentence:</p>
<ul>
<li><strong>Subject:</strong> That <strong>runs</strong> on every message. → subject relative clause</li>
<li><strong>Object:</strong> The subscription calls <strong>that</strong>. → object relative clause</li>
<li><strong>Possessive:</strong> <strong>Its</strong> state is stale. → possessive relative clause</li>
</ul>
<h2 id="heading-03-10-00">Relative clauses are adjective clauses</h2>
<p>A relative clause is a type of <strong>adjective clause</strong> because it <strong>modifies a noun</strong>.</p>
<ul>
<li><strong>Adjective:</strong> a <strong>red</strong> car</li>
<li><strong>Adjective clause:</strong> a car <strong>that is red</strong></li>
</ul>

























<table><thead><tr><th>Clause type</th><th>Function</th><th>Example</th></tr></thead><tbody><tr><td><strong>Noun clause</strong></td><td>acts as a noun</td><td>I know <strong>that he left</strong>.</td></tr><tr><td><strong>Adverb clause</strong></td><td>acts as an adverb</td><td>I left <strong>when he called</strong>.</td></tr><tr><td><strong>Adjective clause</strong></td><td>modifies a noun</td><td>The hook <strong>that we use</strong> is stable.</td></tr></tbody></table>
<p>A relative clause modifies a noun from <strong>after</strong> the noun, so it is also called a <strong>relative adjective clause</strong>.</p>
<h3 id="heading-03-10-01">that-clause vs relative that</h3>
<p>Do not confuse these two uses of <strong>that</strong>:</p>




















<table><thead><tr><th></th><th>Function</th><th>Example</th></tr></thead><tbody><tr><td><strong>Relative that (adjective clause)</strong></td><td>modifies a noun</td><td>The fact <strong>that he left</strong> surprised me.</td></tr><tr><td><strong>That-clause (noun clause)</strong></td><td>acts as a noun</td><td>I know <strong>that he left</strong>.</td></tr></tbody></table>
<p>If <strong>that</strong> modifies a preceding noun, it is a relative pronoun (adjective clause). If <strong>that</strong> fills a noun position in the larger sentence, it is a noun clause.</p>
